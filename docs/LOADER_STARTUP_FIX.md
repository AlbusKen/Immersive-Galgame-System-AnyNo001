# v0.36.60 远端脚本启动失败与门禁禁用

风险 R4：loader、构建入口和发布流程。

## 直接下载证据（2026-10-15）

- 远端 main 为 `6791d681189640503ca20bd6a09be45d99ada61b`，对应 v0.36.59。
- jsDelivr 的该提交 `app/dist/igs.bundle.js` 返回 HTTP 200、`application/javascript`，实际只有 199 字节，正文以 `429: Too Many Requests` 开头。fastly 地址返回相同内容；直接执行下载文件报 `SyntaxError: Unexpected token ':'`。
- 同提交的 GitHub raw 和 jsDelivr `@main` 各返回完整 4759635 字节，SHA-256 均为 `11558e776ccec24e2eae27e4a2b0f0313320810c6337e5dfc53edb248051d829`。GitHub 下载文件直接执行创建 0.36.59 API，随后 shutdown 成功。这证实问题可以不接入酒馆就定位。
- 普通空白浏览器页执行旧 loader：远端模块报上述语法错误，随后仍打印「bundle 已加载」「使用远程版本」，此时 IGS 不存在，已有 `@main` 备用地址没有执行。
- 同一普通浏览器页执行修复 loader：捕获该 SHA 的语法错误，进入已有 `@main` 地址，实际创建 0.36.59 API，临时入口替换成「打开沉浸式Galgame系统」。没有模拟 DOM、注入替代 IGS API 或连接酒馆。

这些是本次直接下载和执行的结果，不据此唯一断言用户设备上的所有启动故障都来自相同 CDN 响应。

## 修改

- loader 的脚本 load 事件不再等价于启动成功；监听目标模块的执行错误，并确认 IGS API 存在且具有设置及阅读器入口。失败清理脚本和监听，然后进入已有备用地址；失败的 latest-ref 缓存不再沿用。
- 删除 package.json 的 gate 命令。AGENTS、CLAUDE 和三份发布工作流明确禁止全量门禁，包括改名、拆开或间接执行的等价流程；不自动执行整套 test / simulate / perf。只有用户明确重新授权才可恢复。
- build 仅生成发布文件，移除自动调用本地启动检查与「gate 成功」输出。构建结果与实际下载、执行结果分别记录。
- 没有新增图片缓存、数据库、轮询或重试队列，保留现有 SHA → main 的有限加载顺序。

## 使用和边界

loader 本身保存在酒馆已导入的脚本里，单独推送 main 不会替换这份源码。需要更新 `loader/igs-loader.json` 自动更新版，才会获得错误识别和备用地址修复；已缓存的坏提交在新 loader 失败后清除。固定版没有打 tag，继续不作为可用发布入口。

真实酒馆和手机未终验，不打 tag；直接浏览器启动只证明该执行环境的结果。不要求用户在手机运行控制台、重启浏览器或导出聊天。
