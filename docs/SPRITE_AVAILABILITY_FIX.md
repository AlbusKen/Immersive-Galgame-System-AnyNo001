# v0.36.51 立绘可用性修复

风险级别 R4：涉及阅读器、素材匹配、中央缓存租约和发布产物。

## 本次现象与根因

用户提供的 v0.36.49 本页诊断为第 74/75 页对白、CG 槽位 19、图片可用数 0、背景为空、立绘给 CG 让位，图片编码缓存为 30.4 MB / 64 MB。该页的直接原因是 CG 标记没有图片却进入 `cgWaiting` 占场分支；与角色有没有立绘、前后页是否同一个说话人无关。

缓存和兜底调查另复现两个问题：当前图片尚未读回时未持有租约，整楼预热可在重绘前淘汰它，并在后续重绘中重复读整楼；字节压力先淘汰较旧的活跃图而非预热图。原装没有目标表情和默认槽时，也可能忽略已有平和或其他同角色图。

## 修复

- CG 标记无图时保留正常背景与角色舞台；CG 地址到达后仍按既有切换、解码和退场流程显示。
- 当前页等待中的主立绘和同台图片先持有中央缓存租约；预热计划只完整执行一次，翻页缺失资源按需读回。字节压力先淘汰无租约资源，仍遵守硬字节预算。
- 保留正常表情及默认匹配优先级，再以同角色平和和其余可用槽兜底；剔除已确认丢图的槽，裸体底图丢失不截断同套兜底，不引入其他角色或其他服装。
- 本页诊断分别报告 CG 标记未就绪和立绘已匹配但原图读取中。

新增生图点的统一结构边界纯函数：所有锚定方式、段落插入和正文变动后的重定位都把点放在完整结构与整行结束之后、独占一行，保留 `<content>` 容器。同一结构多个点保留锚句顺序。阅读旧错插标记时只修正阅读副本，原消息不写回，槽号及绑定不变；重新绘制 CG 时也先整理旧标记再规划。

复用既有缓存、租约和素材匹配入口；新模块与局部 helper 只处理结构边界、当前页资源键和同角色保底图，没有新增像素缓存或持久存储格式。

## 验证与边界

- 修改前：三个定向单测及两个模拟用例均失败，分别证明缓存字节压力、兜底漏图、缺图服装、75 页空 CG 占场和低数量缓存反复读取。
- 修改后：定向缓存 / 立绘 / 预热单测 12/12；定向 CG、当前图及设置器图到达模拟 6/6 通过。
- 锚定修改前新增的 7 个结构边界与旧对白用例全部失败；修改后锚定 / 自动插图单测 86/86，包含 HTML、代码块、CRLF、未闭合结构、多个槽位及幂等读取兼容。
- `npm run gate` 通过：structure、static、单元 2308/2308、模拟 233/233、perf 与 build；性能烟测 3.83ms · map-gen 762ms · reader-source 224ms。正式/调试 bundle 的自动/手动启动四种检查通过。版本为 v0.36.51，loader 源文与固定版 JSON 一致。失败 CG 点仍可重画且不借用其他槽位图片，无图时保留场景。
- 75 页 / 槽位 19 用例是根据诊断构造的正文，未使用真实聊天记录，不能替代原宿主终验。真实酒馆与手机待复验；先推 main 供重载验证，暂不打版本 tag。
- CG 已可显示、HTML 卡片、NSFW 隐藏开关、聊天隐藏开关、旁白离场仍沿用现有前景规则。单个或全部活跃图超过硬字节预算时仍可能无法驻留，本次不通过放大缓存或另存原图绕过预算。
