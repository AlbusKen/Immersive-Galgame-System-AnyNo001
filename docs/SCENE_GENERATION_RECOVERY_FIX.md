# v0.36.61 正文补图与场景差分恢复

风险 R4：场景匹配、生图状态、缩略图和发布文件。

## 修改前的生产函数复现

- 场景主图和时段图都存在，但雨天槽 url 为空：`lookupSceneBackground` 返回 null；把时段 url 也清空，仍不返回场景主图。
- 场景登记 url 为空，生成图库有同场景图：`resolveBackgroundAsset` 返回空图、`needsGeneration: false`。
- 场景原图没保存提示词：首次手动差分返回 done/count 0，写词 0 次、出图 0 次，并持久化 skipped；再次点击返回 nothing-missing。
- 场景原图有日间提示词，夜景出图故意失败：第一次返回 generation-failed，第二次手动返回 nothing-missing，出图总次数仍为 1。
- 数据库生图返回空 Blob：真实 `createImageBackend` 返回 `ok: true`、`data:image/png;base64,`。这些字节不能显示图片，却会被旧状态判断当成完成。

以上使用生产入口、内存 store 和受控图源；没有调用真实模型或修改用户数据库。它们证明这些程序分支存在问题，不把它们等同于用户设备上每一次失败的唯一原因。

## 修复行为

- 空天气/时间槽逐级回落同场景图，已知不可用图也继续兜底；空场景不挡生成图库、本聊天图和默认占位，仍缺图时保留补全需求。
- 原图缺词时复用背景规划队列补写再出图，差分仍关联原图。旧无原因 skipped 可以恢复；同时间原图、用户 discarded 继续跳过。
- 手动补全可重试失败，不依赖自动开关。相同失败在本楼反复重绘时不重复发送，下一楼新需求可再尝试；没有轮询或新重试队列。
- 新图缩略图优先复用已有中央缓存像素，不必先重读文件。CG 空成功改成失败，旧 done 空图也可以补画；再次点击复用已保存提示词直接请求出图，并明确写入日志。
- 两个正文入口保持各自职责：「绘制CG」进入 CG 库；「补全立绘与背景」进入「素材 → 待确认」，当前舞台可显示临时图，正式入库仍由用户选择。
