# test-v0.36.66 固定版本被回退替换修复

风险 R4：loader 源码、固定文件生成、版本与发布产物。用户要求指定 tag 必须就是该版本，不允许加载失败后改跑旧版。

## 本次实际证据

2026-10-15 从公开发布地址取得的响应：

- `cdn.jsdelivr.net/...@test-v0.36.65/app/dist/igs.bundle.js` 及其小时参数地址读取超时，对应提交 SHA 地址也读取超时。
- 固定 tag 的 `manifest.json` 返回 HTTP 503；`fastly.jsdelivr.net` 的同 tag bundle 返回 HTTP 503、`No healthy backends`。
- 旧启动器的 `@main` 后备地址返回 HTTP 200，4,759,635 字节，内容版本明确为 0.36.59，SHA-256 为 `11558e776ccec24e2eae27e4a2b0f0313320810c6337e5dfc53edb248051d829`。
- GitHub raw 的原 `test-v0.36.65` 文件返回 HTTP 200，4,777,232 字节，SHA-256 `d8f3705bf9d490e2ce926235fe7f5cfa531e1c701ab963f18e96695106111c31`，与本地已提交 bundle 完全一致；直接执行创建 0.36.65 API，调用设置入口生成的面板版本为 0.36.65。该执行没有浏览器 DOM，不能冒充手机实际挂载。

使用原 0.36.65 固定 loader，在没有旧实例的环境中模拟已观察到的 tag 请求失败，后备加载上述实际下载的 main 文件：最终 API 为 0.36.59，未弹出错误。这直接复现了跨版本回退，不以“页面已有旧实例”作为本次故障解释。

另有独立的旧实例复用缺陷：只因 `ensureMagicWandEntry` 存在就不再加载指定 tag。这是额外确定性复现，不能替代用户现场的失败原因。

## 修改

- 固定文件将 tag 写入脚本内部 `PINNED_REF`，不再写全局 ref；页面残留 ref/base 无法覆盖本文件指定版本。
- 固定加载计划只包含该 tag，HTTP、模块执行或版本核对失败均明确报错，不请求 main 或其他版本。
- 实际 API 版本必须与 tag 的版本相同。错误版本被关闭并移除，不能让旧版界面冒充新包；错误保留要求版本、实际版本与来源地址。
- 仅来源 ref、base 与实际版本均一致才复用。需要替换时等待旧媒体所有者正常 shutdown；关闭失败即停止。共享关闭 helper 只复用现有生命周期，没有新增公开 API 或后台轮询。
