# v0.36.56 媒体空闲与备份修复

风险 R4：媒体持久化、回收状态、设置提交通知与发布 bundle。内测修复，不以本地证据替代真实酒馆和手机复验。

## 故障与原因

楼层结束很久后，酒馆仍反复打印四种 `igs-*-records.json` 的 Uploaded 日志。旧回收队列把仍被引用的图片留在每 30 秒执行的重试中，每次回收又无条件刷新四份备份。备份函数未比较内容，只有 `savedAt` 改变也会覆盖文件。删除/读取失败和像素搬家失败均没有自动尝试上限。

## 修复

- 已同步的版本、值和删除标记不上传、不更新 `savedAt`。相同内容的重复写入不制造新版本；保留业务操作结果和原有并发校验。
- 回收仅要求真正待同步的备份提交。正式引用保护进入等待状态，取消周期唤醒；最后一个引用解除、配置提交/恢复或启动触发一次复查。候选仍持久保存，便于远程旧设置解除引用后继续回收。
- 临时写入保护等待租约释放事件。崩溃遗留的过期租约在启动或手动重试时复查，不后台扫描。
- 备份和像素搬家共用最多三次自动尝试预算，回收失败也最多三次，达到上限暂停并保留记录。手动重试或真实新变更可以恢复；回收的暂停状态跨重载保留。
- 设置新增「重试待备份记录」，诊断区分等待引用与暂停。相同配置值写入、空删除不触发设置上传。
- 保留全部引用检查、版本合并、写后确认、删除标记和提交锁；缓存容量、字节预算及 LRU 淘汰规则保持既有规则。

## 验证

- 新增 18 项 `media-idle-lifecycle`：稳定楼层推进十分钟、共享图片推进一小时无新增请求；最后一个引用解除后回收；租约释放唤醒；删除和读取失败暂停；暂停跨重载；旧引用启动复查；离线像素、备份失败及共用预算；相同写入；远程更新与备份丢失；并发编辑；配置提交唤醒和设置重试入口。
- 将稳定楼层与共享引用两项回归放到旧版 v0.36.55，均复现失败；修复版通过。
- 首轮 48 项定向回归通过。最终隔离副本完整 `npm run gate` 通过：结构与静态检查、2347 项单元测试、237 项模拟、性能（3.69ms / map-gen 828ms / reader-source 368ms）和构建；压缩/调试包 × 自动/手动四种冷启动通过。loader 构建与产物一致性门禁通过。
- 构建在隔离副本进行；保留原工作区 17 个 WebP 修改，不覆盖、不提交。

## 复验与边界

- 真实酒馆、真实存量图库和手机未终验，不打 tag。推送 main 后，确认加载 v0.36.56，验证一楼与图片任务稳定后不再出现重复 Uploaded；共享图片直到最后一个引用解除才回收；故障后停止自动尝试且可手动恢复。
- 未改变酒馆文件 API 缺少跨设备 CAS 的限制。另一设备释放引用若没有本机通知，候选保留到下一次显式引用复查、启动或手动重试，不能声称跨设备即时回收。
- 所引用的 `功能总集表.md` 当前仓库不存在；依据媒体、storage、core、UI 契约和架构文档核对模块边界。
