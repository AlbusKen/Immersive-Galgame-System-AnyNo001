# test-v0.36.64 演出空转与重复绘制修复

风险 R4：舞台暂停通知、亲密声画调度、发布文件。用户选择保留现有演出，只消除空转和重复绘制；不因手机、静置或正文稳定而自动关闭天气、呼吸和背景运镜。

## 已确认的路径

正文准备与持续动画是两条路径：前者按楼层与变更通知执行，后者可能在一页停留期间持续工作。本轮发现了可从生产代码直接复现的无效工作，不能用楼层数据已稳定来推断演出已经停止：

- 亲密演出的 `requestAnimationFrame` 与固定 50ms 节拍定时器没有接入舞台遮挡/暂停；面板盖住后，仍继续计算和写样式。
- `.igs-rm-front` 没列入现有 CSS 舞台暂停及背景遮挡范围，前景光影可能在不可见时继续动画。
- 静音且减少动态效果时没有可驱动的输出，但因为计划里仍有心率数值，固定定时器继续空转。
- 关闭后已经排入队列的帧没有终止标志；节点被外部移除时也没有像天气粒子那样退出，存在旧循环继续存活的路径。
- 动态 CSS 变量即使数值相同也逐帧写入，反复使样式失效。

## 修改边界

复用现有 `stage-pause` 状态，增加内部 `onStageIdleChange` 通知；合并的暂停/遮挡状态发生变化才通知，不增加观察器或轮询。亲密前景纳入既有 CSS 暂停范围；自动翻页、对话层与面板内部画布保持原有规则。

节拍调度改为按下一次心跳、呼吸、节律或钟声的截止时间提前补排。无声音、无可见动态画面时不保留计时器；画面不可见时停止帧，有意继续播放的音频仍按真实节拍排程。页面隐藏时停止两者，恢复后重建下一拍，不补放整段积压动作。

相同 CSS 变量不再写入。关闭和节点移除清理帧、计时器和订阅，并拒绝迟到回调。没有新增公开 API、图片缓存、后台周期任务或自动画质降级。

## 定向证据

以生产 `syncRomanceIntimate` 和舞台暂停函数，搭配受控时钟、假 DOM、关闭声音的二档亲密演出模拟 60 秒；帧步进 16ms，触屏画面更新原有上限保持不变。

| 状态 | 修复前回调/样式写入 | 修复后回调/样式写入 |
| --- | ---: | ---: |
| 设置面板盖住舞台 | 4687 / 1875 | 0 / 0 |
| 静音且减少动态效果 | 937 / 0 | 0 / 0 |
| 可见，保留亲密演出 | 4687 / 1875 | 约 3816 / 987 |

可见状态仍持续播放用户开启的演出；心率的微小随机变化会使该行计数略有波动。上述为这条演出链的回调和样式计数，不是整个浏览器的 CPU、GPU 或手机温度实测，不据此声称已经解决所有设备发热原因。

只检查 `renderer-idle.test.js`、`stage-pause.test.js` 与 `romance-intimate.test.js`，28 项定向用例通过；覆盖静态无任务、没有帧 API、遮挡与离屏、后台恢复、同页不重复时钟、正常动态保留、关闭与节点移除、迟到帧、原有天气/花瓣暂停恢复，以及亲密演出原有阶段规则。
