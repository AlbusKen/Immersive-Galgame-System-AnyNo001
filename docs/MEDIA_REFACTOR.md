## 原有问题与统一规则

| 原有问题 | 重构后的规则 |
| --- | --- |
| 素材、CG、阅读器、物品、地图各存原图和 URL | 业务只持身份与元数据，像素/缩略图/URL 归中央缓存 |
| 路径当内容，同一图片重复占用磁盘和内存 | 内容去重；路径只是别名，新原图文件统一 SHA-256 命名 |
| 只限张数，不限字节；清理后在途任务回填 | 双预算、世代/token 校验、取消请求/队列/读取、统一销毁 |
| 元数据保存先 hydrate，读失败可能把原图写成空 | 原始记录与显示投影分开；提示词/收藏等不读取像素 |
| 重画前删旧图；引用落盘失败遗留新图 | 先提交新引用再回收旧引用，失败补偿，旧图保留 |
| 导入直接覆盖包内 ID，重复引用与头像分散写 | 分配新 ID、递归重映射、头像一起暂存，恢复引用后回滚图片 |
| 删除失败被忽略，旧备份或旧文件名会复活记录 | 持久队列 + tombstone + 版本化备份，恢复能重建回收任务 |
| 配置和地图备份共同管理同一地图键 | 地图备份为唯一权威，旧配置只在缺少地图备份时迁移 |

| 图片来源 | 持久来源 | 显示 / 派生缓存 | 删除 / 失效 |
| --- | --- | --- | --- |
| 生成/上传背景、立绘、头像、服装、物品 | `igs-generated-assets` images 元数据 + 原图文件；离线时业务库暂存像素 | `asset:<id>`，素材缩略图 `thumb:asset:<id>`，同内容一份字节 | 全部配置、预设、聊天临时资产复查；删除标记与 GC |
| 立绘原图、AI 工作图、透明结果、遮罩 | 四字段文件路径，original 不可变，revision 原子更新 | 仅显示 dataUrl；编辑/导出显式读取各字段 | revision 冲突补偿上传；共享路径保护 |
| 楼层剧情 CG / 过场 CG / NSFW CG | `igs-illustrations` slots + `igs-cg-records.json` | 当前槽 `cg:<floorKey|slot>`；缩略图归中央缓存 | 重画先保旧记录，成功换引用；删除标记防复活 |
| 日常合成照片 | `igs-photo-album` + `igs-photo-records.json` | CG 缩略图与原图显示；合成画布为短生命周期 | 目录/标记是元数据，文件走共享 GC |

| 自定义地图 | 本机 `igs-map-custom:*` 路径 + `igs-map-records.json` | 中央原图缓存，当前地图持租约 | 同键意图与旧值验证，地图 tombstone 为权威 |
| 程序地图底图与灯光 | 确定性输入，可重新生成 | 中央内存像素；生成器只保任务元数据 LRU | 换图/关闭释放租约，清理后按输入重建 |
| 酒馆消息中的外链/智绘姬/柏宝绘图片 | 插件或远程 URL 的所有者 | 浏览器 HTTP 预载；消息关联仅存 URL 与聊天/swipe/revision | 不复制到 IGS 磁盘，不代删外部图片 |
| 用户 URL 素材 / 内置皮肤 / 图标 / 地图美术 | URL 或构建静态文件 | 浏览器 HTTP 缓存与渲染解码 | IGS 清缓存不删除静态发布文件 |
| 上传的旧 inline 头像 | 原配置，迁移后为生成库 ID | 头像缩放、解码为临时操作 | 导入头像一起暂存；配置引用失败补偿 |
| 遮罩编辑、AI 修复候选、画笔撤销 | 接受前仅编辑会话内存；接受后写 revision 事务 | 有界操作缓冲，不是长期图片缓存 | 取消/关闭释放会话；不影响已提交图 |
| 漫画头部/脚底探测 | 可从图片重建的几何信息 | 48 条元数据，inline 内容指纹作键，失败 30 秒过期 | 清理中止旧探测；解码有期限 |
| 独立 `src/dice-system/stable.js` | 无 import 或构建引用的压缩参考脚本 | 其私有头像/icon 缓存不进入 IGS runtime | 保留存档，不将它算作当前 IGS 的第二套缓存 |

generic `createResourceCache` 是兼容导出的资源记录容器，当前运行时没有调用；它不是运行时图片像素缓存。新增图片入口必须接 media，不能沿用它保留原图。

## 存储与提交

- 新文件：`user/images/igs-media/<SHA-256>.<ext>`。HTTP 缺少 WebCrypto 时也使用相同 SHA-256，分片计算避免长时间占用主线程。旧文件路径继续有效，不批量挪动用户现有图库。
- 可再生缓存：`igs-image-cache` v3，files 保存内容 Blob，meta 保存别名/LRU，两者同事务。内存默认 64 MiB，磁盘 192 MiB，内容条目默认 320（1–2000）。活跃页可超条目软限制，字节预算仍是硬限制。
- 持久业务：素材、CG、照片保留各自原数据库的记录 schema；地图保留本机键。`igs-media-journal` 保存 WAL、版本、tombstone、回收任务与写租约，不能被清缓存清掉。
- 备份：`igs-asset-records.json`、`igs-cg-records.json`、`igs-photo-records.json`、`igs-map-records.json`，v2 records；CG 保留旧 slots 兼容字段。备份不内嵌图片字节，只有像素成功搬家才取消待上传状态。
- WAL 准备失败不能写业务数据库。离线像素的 prepared WAL 可暂存原像素，业务提交后移除；未完成日志可重放。保存新图前持写租约，保存新引用后才释放旧文件。
- 备份前重试所有 inline 像素搬家，验证原记录未变后提交，避免覆盖期间编辑的提示词/收藏。坏记录单独报告迁移失败，健康记录仍能备份。自动重试从 2 秒退避到 60 秒。
- GC 先 flush 备份，再在同一提交锁中检查所有媒体记录、远程配置的直接/间接引用、本机所有预设/聊天资产和活跃写租约，删除无引用文件。共享保护与 API 删除失败分别记账；已提交 tombstone 的旧引用可恢复为删除队列。
- 元数据操作不 hydrate 原图。原图读失败只影响显示；编辑/导出缺原图或遮罩时拒绝伪造完整记录。

## 缓存与可见页面

中央层拥有 Blob 和对象 URL，一张内容在内存/磁盘分别只存一份；业务别名可不同。缩略图是不同内容，使用同一预算和失效规则。browser HTTP/解码/GPU 缓存与当前编辑画布不计入编码字节预算，不能用 64 MiB 宣称整个浏览器图片内存封顶。

下载最多四路；请求头、响应体、FileReader、地图画布编码和图片解码有期限。清理取消排队与在途任务、增加世代并撤销 URL；旧任务不得回填，也不得撤销同键的新任务资源。CG 当前页、阅读器舞台和地图底图/灯光持资源租约，换页或关闭释放。销毁会阻止正在查引用的回收任务继续发起物理删除，已发送的酒馆删除请求不能撤回。Web Locks 或 IndexedDB lease 串行协调同源提交和磁盘预算，BroadcastChannel 通知同源页面失效。

旧 v1/v2 像素缓存升级时可清空；CG entries 保留，旧 CG thumbs/asset-thumbs 可重建。旧 16 位内容哈希用真实记录键和图片内容校验，多字段兼容原图/结果/遮罩；slot 1–16 都支持。不可逆的 Unicode/截断 tagged 文件名不猜归属，缺图结果不永久缓存。

## 诊断接口

`IGS.media.stats()` 返回编码字节缓存、下载、活跃资源、持久回收任务、备份脏记录/待上传状态和 origin estimate。`clearCache()` 只清缓存；`flush()` 重试备份；`retryDeletes()` 重试回收；`auditImages()` 返回引用与孤儿记录；`collectImages(ids)` 只接受未被引用的候选并在删除时再次复查。`auditFiles(paths)` 审查提供的 IGS 文件路径，不自动枚举或删除未知历史文件。

设置「备份」页新增查看占用、重试待删除文件；复制诊断包含媒体统计。不会导出真实 API Key、图片 base64 或聊天正文。

残余边界及触发时机：

- 真实酒馆、手机与真实存量图片未验。交付 main 后在目标酒馆复验缓存清理、旧图恢复、批量导入/重画与删除队列；通过后才给脚本同版本打 tag。
- 酒馆文件 API 没有跨设备 CAS/事务或服务端写租约。版本合并、写后读回校验与重试依赖本机日志仍存在，不能保证多设备同时写入无丢失，也不能对另一设备尚未提交的写入提供强删除隔离。同源页面已有锁；跨设备强保证需要后续服务端媒体事务接口，不可在客户端冒充实现。
- 无 IndexedDB 环境会退回进程内存适配器，无法保证浏览器重启后的本机 WAL/队列持久性；酒馆备份成功的记录仍可恢复。系统诊断与调用错误会暴露备份/保存失败。
- 没有可验证归属的旧文件只报告/保留；有合法旧路径的记录继续读取，不自动批量重命名。只有用户确认真实图库迁移/清理后，才在真实数据上执行。
