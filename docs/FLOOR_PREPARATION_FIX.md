# v0.36.62 整楼准备与翻页延迟修复

风险 R4：阅读器准备、场景演出、只读数据库和发布文件。按用户明确要求禁用全量门禁，不运行整套 test / simulate / perf。

## 已确认的问题

拿到完整一楼后，旧实现仍在每页重新定位整楼原文、解析演出与服装、寻找台词归属和同台角色。状态栏选表后每次翻页导出全表；任意素材图读取失败后，当前角色匹配会先检查整个角色库。运行越久，表格和素材越多，这些工作越重。

用户确认的表现是点击后整页延迟切换；仅隐藏台词的 160ms 读图等待不能解释它。

## 准备与补齐边界

- 复用既有最多八楼的阅读源缓存，解析与准备结果同进同出。正文/分页输入、相关配置或聊天改变才重新准备；普通翻页不 hash 同一份原文、不重扫整楼。
- 一次建立原文范围和宽松位置映射，顺序定位重复句子；完整跨行对白/心理结构、CG 独占行规则保留。说话归属、场景、NSFW 连续段、恐怖档位、CG、换装与同台名单都预先按页准备。演出区间和旁白继承顺序累积，不对每一页重跑完整阅读器。
- 整楼预先匹配素材身份并走现有中央缓存预热。页计划不保存 blob 或图片字节。图片被淘汰/后到时按当前需求读取；读图失败、恢复、重画只更新相关图片的匹配，新素材按现有聊天素材键补齐，不使整楼正文失效。
- 当前楼层只保留一个只读表格快照，状态栏、服装与约定共用解析/行索引；本楼角色提前准备。更新回调先使快照失效、再合并刷新。状态栏关闭时，换装也订阅更新；缺 API/读取失败不伪装空表，正常使用入口允许短期重试，没有轮询。
- 新图和数据库变化复用已有通知。关闭阅读器释放源准备结果、表格快照、订阅与合并定时器。没有新增数据库、图像缓存或后台周期任务。

## 定向验证

新增 `app/tests/reader-floor-preparation.test.js` 的 15 项验证：有界准备复用、顺序/宽松原文定位、未来角色预匹配、无关角色不被扫描、单图失败恢复、新素材精准补齐、表格共用和合并失效、关闭状态栏的服装更新、跨行对白/重复短句换场换装、正文/设置更新、CG 规则、演出状态不回写、HUD 行顺序、后到物品定位。

另外只检查直接受影响模块：`event-cg`、`sprite-availability`、`floor-asset-prefetch`、`multiline-directives`、`fx-directives`、`narration-sprite`。八类生产阅读器前后快照逐页一致：多角色心理/旁白、同台离场再出场、反应背影、换装继承复位、短心理按句分页、CG/亲密、卡片聊天室、恐怖档位。

计时使用生产 `createIgsReaderHost`、内存 storage 和受控数据库；关闭打字机，无 DOM；先翻五页，再取三十次 `next` 的中位数。前后版本使用相同样例、分别启动 Node，包含同步表格导出克隆。

| 受控样例 | v0.36.61 翻页中位 | v0.36.62 翻页中位 | 30 次翻页整表导出 |
| --- | ---: | ---: | ---: |
| 80 页，HUD 关闭 | 0.79ms | 0.34ms | 0 → 0 |
| 400 页，HUD 关闭 | 1.67ms | 0.22ms | 0 → 0 |
| 80 页，50 行表 | 0.69ms | 0.13ms | 30 → 0 |
| 80 页，5000 行表，姓名首列 | 13.12ms | 0.20ms | 30 → 0 |
| 同上，数据库直接返回引用 | 11.39ms | 0.17ms | 30 → 0 |

准备工作前移到进入楼层：本次 400 页样例的打开耗时由 23.17ms 变为 47.79ms；5000 行表格样例由 25.22ms 变为 11.96ms。它们包含 Node 的初始化/JIT 差异，只用于说明测量范围与一次准备成本，不代表手机实际延迟，也不声称所有表格格式均有相同提升。

## 剩余边界

首次进入长楼需要一次准备，其移动设备开销仍待正常使用复验。字节预算不足以容纳整楼时，后续页会正常按需读取对应图片；准备结果不承诺把整楼像素长期留在内存。真实酒馆插件的 DOM 布局/绘制和网络耗时不在以上无 DOM 计时范围，若仍出现卡顿，下一步应针对这些剩余路径记录点击到绘制的时间，不能据现有数字宣称手机已完全消除延迟。
