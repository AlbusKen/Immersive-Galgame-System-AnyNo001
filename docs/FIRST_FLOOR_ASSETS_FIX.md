# v0.36.57 首楼素材恢复

风险 R4：素材文件适配、缓存任务、配置事件、阅读器刷新与发布构建。

## 用户现象与复现

酒馆重启后第一轮 GAL 一直黑屏，进入设置器看素材加载后才能恢复。

新数据库使用真实素材文件适配器和已有记录备份，首次直接读取背景与立绘。v0.36.56 会在恢复记录时通过 `acceptRemote` 失效 `asset:<id>` 缓存，取消已经开始的首楼缓存任务；token 变化使完成通知被忽略。下一次设置器读取发生在恢复完成后，因而可能成功。另有配置恢复仅更新 core、未通知当前阅读器重绘的启动缺口。

## 修改

- 素材适配器提供现有 journal 的 `restore` 和已取得记录的 `hydrateImage`，保持原有读写接口。
- 素材服务共享一次元数据恢复，显示和缩略图先完成记录读取，再取得缓存 token 并读像素。保留备份读取失败时的本机记录后备；不修改真正缺图的处理和图片路径。
- 素材模式启用时启动一次元数据恢复，完成后通知阅读器；配置恢复、保存后使当前阅读器重新匹配素材，图片到达继续走已有的合并刷新。舞台已经重绘时清除设置器遮挡产生的过期标记。
- 不新增数据库、像素缓存、轮询或 provider 请求。首楼只按需读取图片，v0.36.56 的无变化不上传与有界回收仍保留。

## 验证

- 两项关键单元复现先在旧实现失败，再在修复后通过：首次图片读取完成通知、背景/立绘并发读取。
- 七项 `asset-cold-start` 单元回归：首次与并发、首张缩略图、备份网络失败的本机后备、清理与停止期间旧任务失效、按需索引的作用范围与分页。
- 两项完整阅读器模拟：当前角色卡内精确时段背景与立绘直接在首楼显示；首楼先打开、配置随后恢复时自动刷新，覆盖初始模式关闭和空库两种状态。均断言没有打开设置器，没有为显示素材上传备份，并验证舞台立绘的实际 DOM 样式。
- 新模拟使用生产 IndexedDB 素材适配器；首次全量验证暴露 mock 缺少 `index.openCursor`，已补齐原生游标查询并验证作用范围、顺序与分页，避免把测试环境错误当作生产恢复错误。旧版单元与两项阅读器场景均复现失败。
- 33 项素材/媒体定向回归通过；隔离副本完整 `npm run gate` 通过：structure、static、2354 项单测、239 项模拟、perf 和 build 全部通过。
- 性能 smoke：4.11ms，map-gen 707ms，reader-source 350ms；压缩/调试 × 自动/手动四种 bundle 冷启动检查通过。loader 已预先构建，发布产物一致性门禁通过。
- 原工作区 17 个 WebP 修改保留，隔离构建后仅同步本轮产物。
