# test-v0.36.65 静态页资源重绘循环修复

风险 R4：阅读器资源完成回调、生成图库显示通知、中央缓存活跃资源的硬预算边界，以及版本与发布文件。保留用户开启的所有演出，不依靠关闭动画或降低画质处理静态页发热。

## 已复现的底层问题

生产 `reader-host.resolveReaderAssetUrl` 忽略 `load()` 的读取结果，在当前页仍引用该图片时无条件调用 `updateMountedReader`。缺图读空后，下一次重绘又遇到缓存未命中，继续读取。没有动画、用户动作或外部 DOM 变化也会持续循环。

使用 esbuild 编译生产 reader host，只把 DOM 绘制换成继续消费当前页图片的受控回调，修复前得到 200 次读取 / 200 次重绘；到 200 次人为截断。这是生产回调反馈路径的复现，不是浏览器 CPU、GPU 或手机温度测量。

生成图库和缩略图还有相同的通知语义错误：中央缓存的 `load()` 可以返回非空结果，但因硬字节预算没有保留该图。原来仍发 `image-loaded`，导致 UI 重新构建页面和再次读取。

## 修复与 LRU 边界

- 阅读器完成回调先核实当前页仍需要该资源，且中央缓存出现此前尚未显示的新地址；读空、拒绝、未接纳、inline 和同步已显示的地址不重绘。当前请求结束后释放去重标记，后续正常读取可重试。
- 在途请求由 Set 改为带身份的 Map，清缓存后的旧完成回调不能删掉同地址的新请求。没有新增缓存、黑名单、轮询或公开 API。
- 原图及缩略图只在中央缓存中已存在可显示地址时发就绪通知。预算拒绝不冒充文件丢失，不永久屏蔽素材。
- 非活跃资源仍按 LRU 淘汰。只有当前页活跃图本身超过硬字节预算时，优先拒绝后来读入的图，避免几张受保护图片轮流挤出、读回并相互触发重绘。离开旧图释放租约后，正常读取可接纳此前未驻留的图。不增加 64 MiB 默认硬预算。

“活跃图片总量超预算”是确定性的边界复现，尚未确认用户手机触发了这一条件。普通缺图导致的第一条循环无需缓存满就能复现。

## 定向证据

`reader-resource-idle.test.js` 直接编译生产 reader host，替换 DOM 绘制以计数，覆盖无演出静态页：

| 场景 | 修复后读取 / 完成回调重绘 |
| --- | ---: |
| 读空 | 1 / 0，静置无新增 |
| 非空结果但中央缓存未接纳 | 1 / 0 |
| 成功取得新驻留图 | 1 / 1，后续读取命中 |
| 同步已经返回显示地址 | 1 / 0 |
| 先读空、再失败、后续正常读取恢复 | 3 / 1 |

同文件还覆盖真实 `resource-cache → tavern-image-files → 中央缓存` 加模拟酒馆文件响应：文件 404 后只下载一次、没有完成回调重绘，文件恢复后明确读取可下载并补显一次。另覆盖并发去重、切页与关闭后迟到结果、清缓存后新旧请求交错、inline 地址、生成图与缩略图预算拒绝、普通资源 LRU，以及两张活跃图总量超硬预算时停止相互挤出并在租约释放后恢复。

本轮 16 项新用例通过；`sprite-recovery.test.js` 与 `media-cache-lifecycle.test.js` 的 16 项相关用例通过。全量门禁及整套 test / simulate / perf 按用户要求禁用。
