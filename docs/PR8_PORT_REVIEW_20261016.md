## 旧立绘到新体系的实际迁移

本轮补全启动、远程设置恢复及所有设置保存/旧资料导入的自动迁移。由 `scene/sprite-system-migration.js` 规划整份新数据，经现有设置保存入口提交后才替换运行时快照。正常显示使用新衣装解析；旧槽读取保留为未完成迁移或保存失败时的兼容路径。

- 每个全局库/角色卡分别处理。旧原装和旧生成槽合并时保持原装优先；同槽不同图另存「旧生成立绘」，不丢引用。命名冲突选择空闲名称，不覆盖已有衣装或衣柜。
- 原默认图保存在衣装 `base`，平和和其他表情保留在 `moods`，不再二选一。没有明确新默认的角色自动映射至迁入的同一套图，显示内容不变；已有明确默认保留。只有衣柜图而没有旧原装的角色使用新衣装解析，不凭空替用户指定默认。
- 自动建立的默认映射标记 `migrated: true`，旧 DNA 的服装线索在适配阶段保持既有显示优先级；用户明确设置默认后移除此标记，旧服装线索不再覆盖新选择。version 2 始终按新衣装规则。
- 全部阅读模式的位置/头部标定与续画注记跟随真实衣装身份。`legacyOriginal: 1` 标记最初迁入衣装，晚到的旧注记仍归入该衣装，不随日后默认选择漂移；重复执行不新增衣装。
- localStorage 多键迁移先写 `igs:sprite-migration:pending`，逐键核验，全部成功才清日志并切换运行时。写入失败补偿旧值；中断重启先恢复旧值再重迁，恢复失败保留日志拒绝继续写。日志不进入酒馆配置镜像。
- 旧续画资料在 `spriteMigrationNotesPending` 为真时保留在持久设置中；备份文件已上传或读回确认同一版本后才移除设置里的副本。上传失败/离线不会丢掉唯一资料。
- 基础图已接入查看、编辑、上传、重画、默认保护及标定处理。旧「设为原装」入口统一为选择默认衣装，不再把图片搬回旧结构。删除角色同步清理旧生成槽和 User 指定，避免下次迁移复活。
- 旧 DNA 不自动升协议或猜测三景别。显式升级后，资料不全时提供「补齐三景别并生成立绘」入口；手改旧图不会使补齐流程被普通重画旁路，衣装缺说明时仍固定原默认的目标名。

迁移只变数据结构与图片引用，不自动调用 LLM/图像生成、下载重编码或重新抠图。显式点击补齐/绘图才进入原有生成流程。此处的保存与中断恢复为本机保护，不承诺不同设备同时编辑的强事务隔离。

## 保留与补齐的当前优化

- 媒体使用同一个有界中央缓存、租约和元数据预算。衣装匹配只保留 `characterKey/outfitName` 轻量投影，不把完整身份、提示词或图片快照放入匹配缓存。
- 保留 WAL、SHA-256 文件卸载、备份恢复、原图不可变、引用保护与持久 GC。CG 基线图片纳入统一图片字段与引用处理；普通相同元数据保存不增加 revision，不重传备份。
- 首楼先恢复记录再创建缓存任务；像素仍按需读取。只有当前页仍需且缓存驻留了新地址才发完成刷新。暂时失败可在后续明确读取恢复，不由完成通知自循环重读。
- 保留整楼准备、八楼有界缓存、当前页优先、按素材身份失效、32ms 合并刷新及舞台遮挡/隐藏时的省电调度。生成、采用和表情绘图补回 `spriteAssetChanged` 精准失效。
- 保留全局加当前卡的有效库，不借其他卡角色/图片；全库引用检查仍可保护其他卡引用，不能把「不参与显示」误作「可删除」。
- 保留副 LLM 酒馆同源后端与凭据隔离、响应体取消；现有严格固定版 loader、User 立绘、旁白与其它演出功能沿用当前版。
- 一致性参考图优先取平和/默认，找到有效参考即停止读取其它表情；比较时只留元数据和图指纹，避免序列化多份 base64。
