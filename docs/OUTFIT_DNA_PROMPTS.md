## 内置 NAI 生图提示框架 v24

先按具体任务选择模块，再按 `outputs.format` 选择该任务的专属规则；共享框架不携带其他任务协议。默认映射如下：

| 任务 | 支持格式 |
| --- | --- |
| 立绘 `sprite` | `sprite-data`、`dna-template`、`caption-slots` |
| 身份资料 `dna` | `sprite-data` |
| 表情 `expression` | `expression-fragments`、`dna-template` |
| 衣装 `outfit` | `sprite-data`、`expression-fragments`、`dna-template` |
| 头像 `avatar` | `dna-template`、`caption-slots` |
| 衣柜提取 `wardrobe` | `caption-slots` |
| 背景 `background` | `caption-slots`、`asset-plan` |
| 物品 `item` | `asset-plan` |
| 普通 CG `cg` | `dna-template`、`cg-plan` |
| 一致性重绘 `consistency` | `dna-template` |

声明 `contentByFormat` 的块遇到缺失或未映射格式时，以 `unsupported-prompt-format` 停止装配。未声明映射的旧自定义块继续使用原正文。编辑器的“分格式规则”使用 JSON 对象；留空移除映射，空对象则显式拒绝所有格式。非法 JSON 只保留在草稿，不参与运行。升级仅在正文及格式映射均未偏离保存基线时整体迁移；恢复默认或指定备份时一并恢复两项，保留角色、顺序和开关。

内容参考根目录 `1001适配gal前端生图预设.json` 中生图预设 `preset-imagegen-97-v5`：`hard-constraints` 对应身份／衣装令牌、图号及本图索引；`main-uid16` 对应身份与当次画面分离；`main-uid3` 对应身份锚点、景别与持续状态；`main-uid20` 对应自然语言画面、当次要求和可见表达。其中“先理解主体、核心动作、对象、接触、空间及取景……”和“默认英文，仅实际渲染的文字保留原文并说明载体。”已复用到画面规则，其余按当前内置任务契约改写，非整套逐字复制。参考文件本身未改；不照搬其中旧默认衣装持久化或一致性衣装来源约定。

普通 CG 的双人物示例在同一个 `slotid` 下交齐两组 Char 与旁路；`---` 只用于完整的不同图片。程序不猜测合并错误分段、不补槽号，也不改写模型正文。旧立绘入口的 `sprite + caption-slots` 使用独立规则，不回退到资料或模板协议。

v17 明确编号正文 CG 的段号交付：`outputs.selection: numbered-text` 时每图在 `slotid` 后写非空正整数 `at`，范围为 `1..outputs.paragraphCount`，多图段号不重复且递增；图号和人物索引不能代替正文段号。`at` 同时决定挂载位置及生成点衣装快照。模板解析前置核验缺号、格式和已提供的段落上限，缺号报告 `field=at, issue=missing`，空值、零、小数及越界报告 `issue=invalid`；失败不读取生成点衣装、不绘图、不猜号或补发。非编号模板仍可省略 `at`，`cg-plan` 按其独立格式保留段号。本地四文件（含完整模拟）648/648、默认升级保护／写失败回滚 2/2、structure/static 和差异空白检查通过；定向 7/7 与四文件重叠。真实模型、收费 NAI、全量、perf 与标准发布构建未在本轮执行，不能据此认定模型漏字段已经消失。工程版本仍为 0.36.8，本地导入件回执见工作区 `.limcode/outputs/igs-local/README.md`；不提交、推送或打标签。

### CG 出镜人物与详细身份 v24

每张 CG 先对照实际出镜者与正文角色标签：凡实际入画且正文有标签的人物，必须逐人交付独立 Char/UC、本人规范键和 token 及完整 meta 字段。玩家、配角、后景、背影和局部出镜者均适用，不能只在 Scene 或他人动作中带过；未出镜的标签人物不强行加入画面。Scene 人数、身份指向与人物组应一致。

每个 named 统一交付非空、详细的 `meta_identity`，按首次立绘同等详细程度描述发色及发型结构、脸型五官、眼型瞳色、固有肤色、骨架体态与适用身份锚点。保留已确定的外貌，在设定内协调落实未限定的普通视觉细节；不以姓名、职业或 sharp eyes 等短句代替，不新增无来源特殊特征或具体身体数值。按实际取景保留适用部位，身份、衣装和本次动态分开。单人及双人完整范例展示详细身份与逐人交付，不区分 DNA 状态安排不同输出要求。

默认框架由 23 升至 24，实际 CG 调用说明和兼容提示同步。Char 仍保留本人身份槽及适用衣装槽，详细身份写独立字段；原有保存身份优先的程序展开机制、严格解析、人物资料供给、永久 DNA 保存及并发调度不变。未手改的默认块沿备份机制升级，自定义 CG 块须先备份再合并或恢复对应默认块。只运行适用语法及静态检查并用既有本地脚本打包，不以提示词字面量或固定回文测试验证模型效果；真实模型遵从与图像效果待重载复验。

### CG 未展开身份模板 v22

普通 CG 的写词回复始终交付未展开模板：每个 named 的正向 Char 恰好保留一次本人 `<<dna:token>>`，衣装模板另保留一次同 token 的 `<<outfit:token>>`，并同时交付非空 `meta_identity`。有无保存 DNA 都不改变这套输出结构，填写身份字段不表示可以删除身份槽或提前将外貌填入 Char。身份与衣装分开，武器和警戒神态不作为稳定身份。

完整单人无 DNA 范例展示身份槽与身份描述同时存在；双人范例保留双方有 DNA、双方无 DNA 及混合资料的统一格式。实际 CG 调用提示与兼容写词规则同步。发送准备仍由既有唯一展开入口逐人选取有效匹配景别的保存 DNA，缺失时才使用本次身份描述，两个来源不叠加；解析器、角色白名单、并发调度与请求次数保持不变。

默认预设由 21 升为 22，沿用已有备份和自定义块保护。未手改默认块可升级；手改块须备份后自行合并或恢复对应默认块。真实模型遵从和图像效果需重载后复验，本地语法／静态检查不能证明漏槽已经消失。

### CG 图头与统一身份格式 v20

普通 CG 的 `dna-template` 模块将图头契约前置：编号正文任务从 `slotid`、`at` 开始，即使单图、空镜或所有人物均无保存 DNA，也必须交付一个有效正文段号。画面涉及多段时选择体现核心动作的一段，不能用段号范围、图号或人物索引代替。提供 `writingRequirements.size` 时，每图显式原样输出尺寸。

每个 named 固定输出非空 `meta_identity` 和允许空摘要的 `meta_signature`，Char 只保留一次自身 DNA 占位符，再接衣装槽及当次动态。有效匹配景别 DNA 优先且原样引用；仅缺身份或景别时，用本次身份描述替换该占位符。保存 DNA 与当次描述二选一，不叠加，摘要不另行拼入 Char；非法保存资料仍拒收。双人完整范例用同一套字段说明双方有 DNA、双方无 DNA、仅一方有 DNA 三种情况，并展示独立衣装、Char/UC 和连续索引；另附多图段号对照与交付检查。身份旁路不混入衣装、灰尘、伤势或动态状态。解析器、身份展开逻辑、衣装快照和请求次数保持不变。

默认预设版本由 19 升为 20，沿用既有升级备份及保护机制：未手改的默认块升级，已手改块保持原文；自定义 CG 块需手动合并或在备份后恢复默认。提示词强化不保证模型永不漏字段，实际遵从仍需重载后以真实模型复验；本轮不发起收费模型或绘图请求。


### 世界书共用参考 v21

立绘、普通 CG 及其他内置写词任务共用独立 `user` 消息 `igs-image-world`，正文以 `{{世界书}}` 放置参考资料。世界书只提供人物与场景背景，不替代本轮正文、构图或已保存身份／衣装。参考自定义预设的 `dialog-world` 职责；不修改根目录预设或依赖 DBG 插件。

正式写词调用酒馆 `getWorldInfoPrompt(scanInput, maxContext, true, globalScanData)`，由原生扫描器决定关键词、常量及其他激活条件，不按人物名无条件抓取条目、不整本注入。扫描窗口按新到旧提供本次 `numberedText`（没有时用 `description`）和已提供的 `previousText`，不额外读取全量聊天。预算与角色卡扫描字段沿宿主口径；各位置已激活的资料汇总到参考消息，不沿用主聊天的插入位置。

扫描期间本适配器串行执行，并恢复作者注释。扫描接口缺失、异常或返回无效时明确停止写词；取消或预设变化后不发送迟到请求。宿主 dryRun 的其他内部副作用及与主生成／其他插件的并发交互仍需真实酒馆复验，不宣称完全无副作用。

`contextMode: provided` 不扫描、不读取世界书字段，并省略动态世界书参考块；一致性重绘继续只用原 CG、本轮裁剪与授权资料。关闭参考块或其顺序项也不扫描。纯预览不调用宿主，示例资料可显式提供 `worldInfo`；注入资料中的占位符不递归展开。

v20 及更早内置存档在已知基线下补入新参考块并备份，保留原有块的自定义正文、角色、相对顺序和开关。后续升级不恢复用户已删除的参考块。独立自定义预设不自动改动，须在 `variables` 声明 `世界书` 并自行添加含 `{{世界书}}` 的共享参考块，保存并激活。

v23 将整个世界书参考消息置于本轮任务资料 `igs-image-data` 之前。v21/v22 已保存默认预设仅在块 ID 顺序仍与已知旧基线一致时跟随新版顺序，并保留原顺序项的开关和配置；手调顺序、增删块或移出顺序的项保持。升级与备份仍在同一预设快照内提交，写失败不改变内存或存储。原生扫描与 `provided` 隔离链路不变；顺序调整不构成真实模型遵从或图像效果的验证。

## 身份与衣装资料

- 首次立绘 `sprite` 的缺失身份候选应形成具体、可复用的外貌设计：保留明确设定，细化未限定的普通发型、五官、固有肤色、骨架及比例。已有身份、已有景别和主动清空状态保持；不得新增无来源的特殊种族、角尾、伤疤、刺青、身份饰品或具体身体数值。用户明确禁止设计时遵守该限制，不用“未知发色／未指定瞳色”等占位凑齐描述。
- 新衣装缺说明时，即使只给衣装名，也应逐件完成主要衣物的具体颜色、材质、剪裁、领袖、开合与内外层结构。破损服从正文，不以尘土、血污或泛称代替服装本身。资料输出格式不等于禁止设计；仅用户明确要求不设计、只照录时不补全未知。
- 立绘资料示例以参考预设 `main-uid27` 的林澄示例为依据，适配为无索引资料字段并展示详细发型、五官、体态与逐件衣装；普通细节补全是示例设计，不是本轮角色资料。三处立绘／新衣装调用提示与该职责对齐；合批调度、严格解析和采用门禁保持。
- 普通 CG 对每位具名出镜者统一要求立绘同等详细程度的当次身份描述，保留已确定外貌并协调落实未限定的普通视觉细节，不登记永久 DNA 或三景别候选；程序仍按既有来源优先级展开。一致性重绘只使用本次授权身份与冻结衣装。已保存的简略 DNA 和衣装不会因更新自动扩写，需用户自行编辑。
- 新身份先形成详细英文母版，再仅删除画外部位短语，生成全身、半身、头像三景别。共同描述的单词、修饰语、标点、顺序和结构逐字一致，不分别改写。已有身份与主动清空状态保持。
- 性格独立保存在 DNA 对象顶层 `personality`，不复制到三个景别；展开时通过既有 `<<dna:token>>` 与所选外貌主语合并。旧记录缺键不自动补写，显式空值保留；缺失资料先生成候选，经图片权威回读与采用门禁后保存。
- 默认、自动、换装及普通素材页立绘重画由程序根据当前 DNA 和衣装组装默认构图，不沿用历史剧情动作。AI 通过 `sprite-data` 整理稳定外貌、独立性格及衣装，首次候选和新衣装按上述权限细化；表情差分通过 `expression-fragments` 返回面部正负片段，替换默认平和表情，不重写人物、衣装、姿势或背景。
- 旧非平和表情恢复记录缺少独立片段时，只重新提取该表情；人物或衣装错绑拒收。手改 `final/exact` 定稿仍原样发送，历史图片及来源快照保留。
- 首次建立服装 DNA 时，保留正文及资料已明确的设定；未指定的颜色、材质、剪裁、层次及必要配饰由立绘 AI 一次协调补全，不需要额外声明允许设计。每件主要衣物分别绑定颜色，后续差分复用保存结果。
- 已保存衣装不自动扩写；用户明确要求仅提取、不设计时，不补全未知细节。设计不凭空增加武器、损伤或人物身份标志。
- 衣装名称是绑定键，不属于设计补全范围。正文服装栏或本次 `outfit.name` 已有名称时，资料协议的 `outfit_name` 或完整画面协议的 `meta_outfit_name` 逐字沿用；中文名保持中文。英文要求只针对描述。新默认衣装与手动新衣装须保存、回读并复核目标后才绘图；保存失败零绘图，绘图失败保留已保存的衣装，采用图片后才设默认。
- 独立衣柜 `outfit-dna/caption-slots` 提取、头像及 CG 完整画面协议保持各自用途；自动补立绘继续经过候选审核，不因资料提取而提前采用。
- 立绘任务示例使用无索引的 `sprite-data` 字段：`dna_full_body: 英文主语`，不混用完整画面的 `meta_dna_full_body: 索引 | 值`。`character` 按当前槽唯一 token 对应的 `characterKey` 逐字填写；角色键、token 与 DNA 中的英文名用途不同。完整画面的 Char／meta 规则明确限于 `dna-template`，解析与角色绑定仍严格校验。

默认正文通过既有版本升级、备份和按块恢复机制更新，保留用户自定义正文、格式映射、顺序、角色及开关。自定义活动预设须按具体任务及 `outputs.format` 对齐所需协议；本次仅面向 IGS 内置 NAI。根目录外部预设保持原文件。

## 自动立绘、临时显示与 CG 衣装

- 自动补立绘仍按人物补一张，直接记录首次触发该人物补图的角色标签中的服装原名，供写词强调及程序绑定；不借后续标签或楼末换装。模板回复在原有衣装校验前，按本批图号与规范人物键固定已有衣装元数据的名称，模型仍负责服装描述。模板上下文、生成快照和候选记录使用同一原名；触发标签未写服装栏时，沿既有首次出场与继承规则。
- 旧生成入口有衣装元数据时也固定原名，未提供元数据时只记录本次 `outfitName` 来源，不伪造生成快照。外部插件先行拒收时仍停止，不绕过其门禁。
- 角色没有任何正式立绘 URL 时，按规范人物名显示本聊天有效 `review`／`chat` 临时图，不要求衣装名或快照匹配；显示结果的 `outfit` 留空，不把正文服装冒充本图实际衣装。已有正式立绘时，显式衣装仍要求版本 1 单角色生成快照与精确衣装名。别名归约后须唯一绑定，不同人物不借图。显示不入柜、不登记 DNA、不设默认。正式图及既有默认回退优先，已登记 URL 的读取／解码失败不视为“从未有图”。
- 内置编号正文 CG 在解析回复时，先按返回的 `at` 取得生成点衣装，再执行原有精确校验，避免楼末衣装提前拒绝前段合法衣装；错名与无效生成点仍停止绘图。历史重画保持原图衣装快照。
- 公共衣装校验保持：同名保存条目重复、错误绑定、缺失描述或保存说明被改写仍拒收。自动补立绘的显式原名由程序绑定，其他任务继续核对回复名称；CG 沿用既有实现。扁平解析器的 `meta_outfit_name` 缺失／重复／格式错误仍拒收。
- 用户现场的 `outfit_name` 报错仍缺完整受控诊断，尚不能确认来源、分支或两侧原值，不宣称已定案现场唯一根因。若更新后仍出现，请提供图像来源、操作入口及实际 `stage/code/field/issue/slotId/captionIndex/lineNumber`，不要发送凭据、完整回文或图片载荷。
